# Architecture: THẢO LUẬN NHỎ: CÓ NÊN THÊM BUILD VERSION VÀO FOOTER CỦA OCEANTECHAI?

## Overview
Technical architecture for displaying application build version in the global footer and via a read-only API endpoint.

## Chosen Solution
1. **Build-time injection** — `next.config.ts` reads `package.json` version and sets `APP_VERSION` / `BUILD_DATE` env vars at build.
2. **Server service** — `BuildVersionService` sanitizes semver and returns `{ version, buildDate }`.
3. **Footer component** — `AppFooter` server component renders version in founder, projects, and workspaces layouts.
4. **API endpoint** — `GET /api/v1/build-version` for programmatic checks (monitoring, QA scripts).

## Design Decisions
- Semver-only output; commit hash excluded from phase 1.
- Version sanitized with regex before render/response (Red Team mitigation).
- Footer uses server-side service directly (no client-side fetch required).
- API returns cache headers (`max-age=3600`) to reduce load.
- i18n keys under `common.buildVersion` for EN/VI.

## Data Model
No database changes. Version is derived from filesystem/env at runtime.

## Risks & Mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| Version info disclosure | Low | Only semver exposed; no commit hash or internal paths |
| XSS via version string | Medium | Semver regex validation; server-rendered text only |
| Stale version in prod | Medium | Build-time env injection from package.json |
| API abuse | Low | Read-only, cacheable, no sensitive data |
