# Feature: THẢO LUẬN NHỎ: CÓ NÊN THÊM BUILD VERSION VÀO FOOTER CỦA OCEANTECHAI?

## Summary
Việc thêm thông tin build version vào footer là một cải tiến hợp lý để hỗ trợ kiểm tra và quản lý phiên bản, nhưng cần đảm bảo cập nhật tự động để tránh gây hiểu lầm. Không cần thiết phải hiển thị commit hash trong giai đoạn đầu trừ khi có yêu cầu cụ thể.

## Chosen Solution
Hiển thị semver từ `package.json` (tự động inject lúc build qua `next.config.ts`) trong footer toàn cục và qua API `GET /api/v1/build-version`. Không hiển thị commit hash.

## User-Facing Behavior
- Footer hiển thị `v0.1.0` (hoặc phiên bản hiện tại) ở cuối mọi trang chính (Executive, Projects, Workspaces).
- Nội dung footer được dịch EN/VI qua next-intl.
- Phiên bản cập nhật tự động khi bump `package.json` và rebuild.

## Alternatives Considered
- Hiển thị commit hash — từ chối ở giai đoạn đầu (information disclosure, chưa cần thiết).
- Hardcode version trong component — từ chối (dễ lỗi thời).
- Chỉ API, không footer — từ chối (Founder cần nhìn thấy ngay trên UI).

## Reasoning
- Giúp Founder và QA xác nhận deployment đúng phiên bản.
- Semver từ package.json là nguồn sự thật duy nhất, đồng bộ với release process.
- Server component đọc version trực tiếp — không cần client fetch cho footer.

## Risks
- Lộ thông tin phiên bản cho attacker — mitigated: chỉ semver công khai, không hash/env nội bộ.
- Version string injection — mitigated: sanitize semver trước khi render.
- Version lỗi thời nếu không rebuild — mitigated: inject tại build time qua `APP_VERSION`.
